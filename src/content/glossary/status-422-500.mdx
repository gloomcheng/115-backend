---
term: 422 / 500
definition: 422 是 Server 讀懂了 Request、拒絕它的內容，該改的是送出的資料；500 是 Server 自己出錯，該改的是 Server 的程式。
category: 網路
first: 1
---

`422` 的 Response Body 會指出哪裡不對，Server 仍正常運作，重送同一份 Request 不會變好。`500` 的 Body 只有 `Internal Server Error` 純文字，真正的線索在 Server 終端機的 traceback，而且壞掉的是那一條路由，不一定是整個 process。

更上層的規則是 `4xx` 屬於這一次請求的問題，`5xx` 屬於伺服器端的問題。`401` 與 `403` 也是 `4xx`，但它們說的不是「這份 Request 的內容要改」，而是「你是誰」與「你能不能做」，見單元 11。

`422` 最難被依賴，因為它沒有跨實作的一致性：同一個 client 錯誤在 Django REST framework 會回 `400`，規格指派給衝突的 `409` 也常被 `422` 頂替，Client 若直接讀 `detail[0].loc` 就綁死了框架。串接別人的 API 時，`400`、`409`、`422` 都要當「資料要改」處理，並且先讀對方文件。
