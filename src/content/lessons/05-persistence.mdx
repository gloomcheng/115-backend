## 01. dict 活不過一次執行

先看前兩行輸出：

<Terminal title="bash — the dict case" flavor="output">{`
$ python store.py dict-add
added carol to a dict, held by this process only

$ python store.py dict-list
dict sees: ['alice']
`}</Terminal>

`dict-add` 確實把 `carol` 放進去了。`dict-list` 也確實是一個新的執行——它看不到 `carol`，因為 `carol` 住在**剛才那個行程的記憶體裡**，而那個行程已經結束了。

這就是為什麼 `fastapi dev` 沒有 `--reload` 時，你重啟一次 Server，先前 `POST /users` 建立的資料就會不見。`examples/http-api/main.py:8` 的 `users` 就是這種東西。

<Callout type="important" title="這不是 bug，是 dict 的定義">
  Python 的 `dict` 是一個執行行程內的物件。行程結束，它就結束。要讓資料活過行程結束，必須寫進**行程之外**的東西。接下來兩種寫法，都在做這件事。
</Callout>

## 02. 文字檔：活下來了，但只是一串字

<Terminal title="bash — the JSON case" flavor="output">{`
$ python store.py json-add
added carol to users.json

$ python store.py json-list
users.json sees: ['alice', 'carol']

$ ls -l users.json
-rw-r--r--  1 you  staff  56 users.json

$ cat users.json
{"alice": {"name": "Alice"}, "carol": {"name": "Carol"}}
`}</Terminal>

`carol` 活過了行程結束。檔案裡的 56 個位元組就是你用 `cat` 看到的東西——**沒有藏起來的東西**。你可以用任何文字編輯器改它，`git diff` 也看得懂它改了什麼。

這是文字檔最大的優點，也是它最大的問題：因為它是純文字，**兩個程式同時改它時，沒有任何機制會告訴你其中一個改動不見了。**

<Terminal title="bash — two writers, one text file">{`
$ python json_race.py A & python json_race.py B & wait
writer A: read the file, writing back in 1 second
writer B: read the file, writing back in 1 second
writer A: wrote the file
writer B: wrote the file

$ cat users.json
{"alice": {"name": "Alice"}, "writer-B": {"name": "B"}}
`}</Terminal>

**`writer-A` 不見了，而兩個 writer 都說「我寫好了」。** 沒有錯誤訊息、沒有例外、沒有任何地方留下紀錄。

`json_race.py` 的核心只有四行（先讀、再加一個 key、最後寫回），你可以自己去讀：兩個行程都「讀整個檔案 → 加一個 key → 寫回整個檔案」。B 讀到的版本裡還沒有 A 的改動，所以它寫回去的時候，把 A 的改動一併蓋掉了。這種「兩個同時寫入、彼此蓋掉」的結果就叫 lost update—— 資料蓋掉了，而且沒有人知道。

<Callout type="warning" title="這一課最該記住的一句話">
  資料不見了，而且沒有任何人被告知。這是文字檔最危險的地方——不是它存不住資料，是它在**存不住的那一次完全沒有聲音**。單元 08 CRUD 與單元 10 驗證會處理怎麼預防它。
</Callout>

## 03. SQLite：檔案裡連結構一起存

<Terminal title="bash — the SQLite case" flavor="output">{`
$ python store.py sqlite-add
added carol to notes.db

$ python store.py sqlite-list
notes.db sees: ['carol']

$ ls -l notes.db
-rw-r--r--  1 you  staff  8192 notes.db
`}</Terminal>

同一筆資料，檔案是 8192 bytes 而不是 56。多出來的不是資料，是**結構**。

先確認這不是文字檔：

<Terminal title="bash — the file itself" flavor="output">{`
$ file notes.db
notes.db: SQLite 3.x database, last written using SQLite version 3053004, file counter 2, database pages 2, cookie 0x1, schema 4, UTF-8, version-valid-for 2
`}</Terminal>

然後問它自己有什麼表：

<Terminal title="bash — the structure lives inside the file" flavor="output">{`
$ python store.py sqlite-schema
CREATE TABLE notes (id INTEGER PRIMARY KEY, text TEXT NOT NULL)
`}</Terminal>

`NOT NULL`、`INTEGER PRIMARY KEY` 這些規則**寫在檔案裡**，不是寫在你的 Python 程式裡。這是關鍵差異：你的程式結束了、換了一個人維護，規則還在。

<Callout type="note" title="為什麼一個檔案要 8192 bytes">
  SQLite 把磁碟空間切成固定大小的 page（預設 4 KB），一次配置兩頁。空的資料庫也會占掉這些空間。檔案大小不是資料量，這一點在單元 08 討論磁碟與容量時會再遇到。
</Callout>

## 04. SQLite 會替你守住型別

規則既然在檔案裡，就會被執行。試著塞一個不合型別的值：

<Terminal title="bash — a type violation the file will not accept">{`
$ sqlite3 notes.db "INSERT INTO notes (id, text) VALUES ('carol','x');"
Error: stepping, datatype mismatch (20)

$ sqlite3 notes.db "SELECT id, typeof(id) FROM notes;"
1|integer
`}</Terminal>

`id` 宣告成 `INTEGER PRIMARY KEY`，餵 `'carol'` 進去被拒絕了，而且 `typeof(id)` 確認留下來的是 `integer`。

同一件事用 JSON 做會怎樣？文字檔沒有「欄位型別」這種東西，因為它本來就只是字串。要擋下來，你得自己在 Python 裡寫檢查，而且每一個寫入的地方都要寫一次。

<Callout type="important" title="這是資料庫的真正價值">
  不是「資料存在檔案裡」——文字檔也有。是**規則跟資料放在同一個地方**，而且由同一個引擎執行。這一點到單元 08 講交易時會變得更清楚：規則和資料在同一處，才能一起被保護。
</Callout>

## 05. 同時寫入：一個拒絕，一個不說話

把第 02 節那個安靜的失敗，和 SQLite 放在同一個實驗裡。`hold_the_lock.py` 讓 writer A 獨占寫入鎖三秒：

<Terminal title="Terminal 1 — take the write lock">{`
$ python hold_the_lock.py hold
writer A: holding the write lock for 3 seconds
`}</Terminal>

三秒內在 Terminal 2 送出第二個 writer：

<Terminal title="Terminal 2 — write anyway" flavor="output">{`
$ python hold_the_lock.py write
writer B: refused -> database is locked
`}</Terminal>

兩段都跑完之後，資料庫裡是什麼：

<Terminal title="bash — nothing was silently lost">{`
$ sqlite3 notes.db "SELECT id, text FROM notes;"
1|carol
2|writer A
`}</Terminal>

**writer B 被拒絕了，而這正是重點。** 它知道自己沒寫進去，所以它可以重試、可以回報給使用者、可以在 log 留下紀錄。

把兩個實驗並排看：

| | `users.json` | `notes.db` |
| --- | --- | --- |
| 兩個 writer 同時寫 | 兩邊都回報成功 | 第二個收到錯誤 |
| 丟掉的資料 | 有，靜靜地丟 | 沒有 |
| 你知道出事了嗎 | **不知道** | 知道 |

<Callout type="important" title="拒絕比丟資料好">
  `database is locked` 是一句你可以在程式裡接住的訊息。你可以讓它等待、可以重試、可以回 `503` 給 Client。一個沒有錯誤的資料遺失，你連從哪裡開始查都不知道。
</Callout>

## 06. 什麼時候該用哪一種

這一課不需要你背規則。只需要問三個問題：

| 你在做的事 | 用哪一種 | 為什麼 |
| --- | --- | --- |
| 暫存資料、測試用、單一使用者 | `dict` | 行程結束就丟，正好是你要的 |
| 設定檔、要進 Git 的資料、人工要能讀能改 | 文字檔 | `git diff` 看得懂，人手改得動 |
| 會被讀寫的資料、多個程式會同時動它 | SQLite | 規則跟資料同住，並發時會拒絕你 |

**判斷的關鍵不是資料量，是「會不會有別的程式同時寫」。** 單機、單一行程的筆記本工具，文字檔完全夠用，強迫自己上資料庫只會增加複雜度。反過來，一旦有第二個執行緒或第二個程式會動同一份資料，文字檔的安靜失敗就變成你必須處理的問題。

真實系統還有第三層：一個跑在別台機器上的伺服器（PostgreSQL、MySQL），行為規則跟 SQLite 相同，但多了網路與權限。單元 08 會先讓你在本機的 SQLite 上把規則與交易看清楚，再談放到網路上。

<Callout type="note" title="這門課用的是 Python 內建的 sqlite3">
  `import sqlite3` 就有了，不需要安裝任何東西，也不需要啟動一個資料庫伺服器。它是一個函式庫，直接操作一個檔案。這是它最適合課堂練習的原因。
</Callout>

## 07. 終端實戰驗證：三次對照

上面每一節的結論都要自己重跑一次才會記住。三種存法、三組對照，全部在 `exercises/05-persistence/` 執行，先清掉舊檔案讓結果乾淨：

<Terminal title="bash — clean start">{`
cd exercises/05-persistence
rm -f users.json notes.db
`}</Terminal>

### 第一步：dict 活不過執行

<Terminal title="bash — step 1" flavor="output">{`
$ python store.py dict-add
added carol to a dict, held by this process only
$ python store.py dict-list
dict sees: ['alice']
`}</Terminal>

`carol` 不在裡面。ls 也證明它沒留下檔案。

### 第二步：文字檔活著，而且你看得懂

<Terminal title="bash — step 2">{`
$ python store.py json-add && python store.py json-list
$ ls -l users.json
$ cat users.json
`}</Terminal>

`carol` 在裡面，而且檔案是純文字。

### 第三步：SQLite 活著，而且檔案裡有規則

<Terminal title="bash — step 3">{`
$ python store.py sqlite-add && python store.py sqlite-list
$ ls -l notes.db
$ file notes.db
$ python store.py sqlite-schema
`}</Terminal>

`CREATE TABLE notes (id INTEGER PRIMARY KEY, text TEXT NOT NULL)` 這行是從檔案裡讀出來的。

### 第四步：把兩個 writer 的結果比一比

<Terminal title="bash — step 4, text file">{`
$ rm -f users.json
$ python store.py json-add
$ python json_race.py A & python json_race.py B & wait
$ cat users.json
`}</Terminal>

對照第 02 節那個安靜的失敗：文字檔這邊兩邊都說寫好了，其中一筆不見了。

<Terminal title="bash — step 4, SQLite">{`
$ python hold_the_lock.py hold &
$ python hold_the_lock.py write
$ sqlite3 notes.db "SELECT id, text FROM notes;"
`}</Terminal>

writer B 被拒絕，而資料庫裡沒有任何一筆是缺的。

7. 用一段話回答：`users.json` 與 `notes.db` 都把資料存下來了，那 `notes.db` 多做的事是什麼？不要寫「比較安全」，寫出你親眼看到的那件事。
8. 回答：你的期末專題會不會有兩個程式同時寫同一份資料？根據第 06 節那三個問題，你會選哪一種？
