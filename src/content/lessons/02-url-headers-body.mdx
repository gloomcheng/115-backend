## 01. URI 是總稱，URL 是其中一種定位方式

你在瀏覽器網址列輸入的字串，通常叫 URL。它告訴 Client 要使用哪種協定、找哪個主機、請哪個資源。

URI 是較大的總稱：只要一個字串能識別某個資源，就可以稱為 URI。URL 是帶有定位方式的 URI。`https://example.com/users/alice` 同時是 URI 與 URL；`urn:isbn:9780131103627` 可以識別一本書，但不告訴瀏覽器要連哪台主機，因此不是用來直接連線的 URL。

這一週先使用一個實務上夠用的 URL 形狀：

<Terminal title="URI — common URL shape" flavor="output">{`
scheme://[userinfo@]host[:port]/path?query#fragment
`}</Terminal>

RFC 3986 定義的是 URI 的通用語法。文件若要精確談語法，看到 `URI` 就先不要自行換成「網址」；「網址」是課堂上方便使用的日常說法。

這裡不靠空白字元對齊。每個標籤都直接指向 URL 中的實際字串；真正的語法要看分隔符號。每一段負責的事不同：

| 部分 | 例子 | Client 用它做什麼 |
| --- | --- | --- |
| `scheme` | `https` | 決定使用哪種 URI 存取方式；HTTP 網頁常見 `http` 與 `https` |
| `userinfo` | `user` | 語法上可以放在 authority 前面；不要把密碼、Token 或 API key 放進 URL |
| `host` | `api.example.com` | 找到要連線的主機名稱或 IP 位址 |
| `port` | `8443` | 指定主機上的網路入口；省略時由 scheme 的預設規則決定 |
| `path` | `/users/alice` | 指出要操作的資源路徑；最後怎麼解讀由 Server 的路由決定 |
| `query` | `active=true` | 把篩選、排序或其他參數交給 Server；它不是另一條 path |
| `fragment` | `profile` | 指向 Response 內容中的位置，由 Client 處理，不送給 Server |

`host` 是完整的主機名稱。`api.example.com` 裡的 `api` 常被叫作 subdomain，`example.com` 常被叫作 domain；這是命名與 DNS 的分工，不要把它們和 HTTP path 混在一起。

`http` 預設使用 port `80`，`https` 預設使用 port `443`。其他 scheme 也有自己的常見入口，例如 `ftp` 常見 port `21`；這些是協定或服務的約定，不是 URL 語法自己決定的數字。URL 沒寫出來，不代表連線沒有 port；Client 仍然要依 scheme 選擇連線入口。寫成 `https://api.example.com:8443` 時，`8443` 才是明確指定的非預設 port。

如果 URL 沒寫 path，Client 會請求 `/`。Server 要不要把 `/` 對應到 `index.html`，是 web server 或框架的設定，不是 URL 規則自動補上的檔名。

## 03. URL 怎麼變成 Request Target

瀏覽器或 `curl` 解析 URL 後，會把其中需要送給 Server 的部分組成 Request。`scheme` 與 `host` 會影響連線；在 HTTP/1.1 的一般 Request 中，Request Target 主要看到 path 與 query，Host 則放在 Header。

<Terminal title="HTTP — URL becomes a request" flavor="output">{`
URL:
https://httpbin.org/get?course=115&topic=uri#fragment

Request:
> GET /get?course=115&topic=uri HTTP/1.1
> Host: httpbin.org
> User-Agent: curl/8.x
>
`}</Terminal>

這裡有三個可驗證的界線：

- `https` 決定 Client 使用 TLS 保護連線。
- `httpbin.org` 出現在 `Host` Header，讓 Server 知道這個 Request 要交給哪個 host。
- `#fragment` 沒有被送出。它是 Client 讀完 Response Body 後，用來定位內容的提示。

<Callout type="important" title="Fragment 不是秘密通道">
  Fragment 不送到 Server，不代表整個 URL 都不會留下紀錄。`path` 與 `query` 可能出現在 Browser history、Server log、proxy log 與分析工具中。密碼、Token、API key 不要放在 URL；改用 HTTPS 也不會讓它們從 log 消失。
</Callout>

## 04. Header 與 Body 放的不是同一種資料

Header 是 Request 或 Response 的附加欄位。它描述這個訊息的格式、來源、快取條件或認證資訊。Body 是訊息內容本身；不是每一個 Request 都有 Body。

一個讀取 Request 可能只有 Request Line 與 Header：

<Terminal title="HTTP — GET has no request body" flavor="output">{`
> GET /users/alice HTTP/1.1
> Host: api.example.com
> Accept: application/json
>
`}</Terminal>

一個建立資料的 Request 可能把 JSON 放在 Body：

<Terminal title="HTTP — POST body" flavor="output">{`
> POST /users HTTP/1.1
> Host: api.example.com
> Content-Type: application/json
>
> {"name":"alice"}
`}</Terminal>

空白行把 Header 與 Body 分開。`Content-Type` 告訴 Server 怎麼讀 Body；它不會把 Body 變成 URL，也不會替 Server 決定資料一定有效。

## 05. Path parameter、query parameter 與 FastAPI 路由

目前範例 API 有這條路由：

<Terminal title="Python — existing route" flavor="output">{`
@app.get("/users/{name}")
def get_user(name: str):
    ...
`}</Terminal>

當你送出 `GET /users/alice`，FastAPI 把 path 中的 `alice` 放進 `name`。這是 path parameter。

Query parameter 在 `?` 後面：

<Terminal title="HTTP — path and query" flavor="output">{`
GET /users/alice?active=true HTTP/1.1
`}</Terminal>

`/users/alice` 仍然是 path；`active=true` 是 query。兩者最後怎麼影響資料，要看 Server 的 handler 是否讀取它。網址長得像有參數，不代表程式一定會使用參數。

## 06. 用 curl 把每個界線找出來

依序執行：

<Terminal title="bash — inspect URL boundaries">{`
curl -v 'https://httpbin.org/get?course=115&topic=uri#fragment'
curl -v 'https://httpbin.org/anything/users/alice?active=true'
curl -i -X POST 'https://httpbin.org/anything/users' \\
  -H 'Content-Type: application/json' \\
  -d '{"name":"alice"}'
`}</Terminal>

每一次只記四件事：

1. URL 的 `scheme` 與 `host` 是什麼。
2. `> GET` 或 `> POST` 的 Request Target 是什麼。
3. 哪些資料在 Header，哪一段是 Body。
4. `#fragment` 有沒有出現在送給 Server 的 Request。
